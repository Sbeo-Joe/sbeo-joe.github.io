<mark>100만 명</mark>의 여권과 운전면허증이 비밀번호 없이 누구나 볼 수 있는 상태로 인터넷에 노출됐다. 호텔 체크인 시스템을 운영하는 기술 업체가 클라우드 스토리지 설정을 '공개(public)'로 방치한 결과다. 설정 실수 한 번이 <span class="hl-red">역대 최대 규모 중 하나의 신분증 정보 유출</span>로 이어졌다.

## 핵심 포인트

- 호텔 체크인 시스템 업체, 클라우드 스토리지를 **공개(public)** 상태로 방치
- 여권·운전면허증 `100만 건` 이상 — 비밀번호 없이 누구나 접근 가능했던 기간 불명
- 피해자 국적·이름·신분증 번호·주소 등 <span class="hl-red">고가치 신원 도용 정보</span> 포함

## ☁️ 클라우드 '공개 버킷' 문제: 반복되는 재앙

이번 사건은 새로운 유형의 사이버 공격이 아니다. 클라우드 스토리지(AWS S3, Azure Blob 등)의 접근 권한을 실수로 '공개'로 설정해 민감한 데이터가 노출되는 패턴은 이미 수십 번 반복됐다.

> "가장 정교한 해킹보다, 단순한 설정 실수가 더 많은 데이터를 유출한다."

이 사건이 특히 심각한 이유는 유출된 정보의 종류다. 여권과 운전면허증은 신원 도용(Identity Theft)에 사용되는 최고 등급의 개인정보다. 신용카드 번호는 사용 중지·재발급으로 피해를 차단할 수 있지만, 여권 번호와 생체 정보가 담긴 신분증 데이터는 한 번 유출되면 사실상 영구적 위험이 된다.

연결고리 분석:
- 1차: 클라우드 공개 설정 → 여권·신분증 데이터 무방비 노출
- 2차: 다크웹 유통 → 신원 도용·사기 범죄에 악용
- 3차: 피해자 금융 사기·비자 위조 등 장기적 피해 지속

## 🔍 이 사건이 드러낸 공급망 보안의 맹점

| 취약 지점 | 내용 |
|-----------|------|
| 3rd Party 벤더 | 호텔이 아닌 시스템 업체의 설정 실수 |
| 클라우드 설정 | 기본값(default) 보안 정책 미적용 |
| 데이터 보존 정책 | 체크아웃 후에도 신분증 데이터 영구 보관 |
| 접근 로그 부재 | 얼마나 오래, 누가 접근했는지 불명 |

호텔 투숙객 입장에서 흥미로운 점은, 이 유출의 책임이 호텔이 아닌 체크인 **시스템 공급 업체** 에 있다는 것이다. 소비자는 호텔을 믿고 신분증을 제시하지만, 실제 데이터는 제3자 기술 업체의 클라우드에 저장된다. 이 공급망(supply chain)의 보안 취약점은 오늘날 거의 모든 디지털 서비스에 존재한다.

## 🛡️ 기업과 소비자가 취해야 할 대응

<span class="hl-blue">기업 관점</span>: 클라우드 보안 설정 자동 감사(audit) 도구(AWS Trusted Advisor, Azure Security Center 등) 도입이 필수다. 개인정보 보호법(GDPR, CCPA) 위반 시 벌금이 수백만 유로에 달할 수 있어 규제 리스크도 크다.

<span class="hl-red">소비자 관점</span>: 이번 사건의 피해자가 자신의 데이터가 노출됐는지 알 방법이 없다는 점이 가장 큰 문제다. Have I Been Pwned(haveibeenpwned.com) 같은 서비스로 이메일 유출 여부를 주기적으로 확인하고, 신용 모니터링 서비스 가입을 권장한다.

클라우드 시대의 데이터 보안은 정교한 해킹 방어보다 기본적인 설정 관리에서 무너지는 경우가 더 많다. 이번 사건은 그 교훈을 다시 한번 확인시켜 준다.
